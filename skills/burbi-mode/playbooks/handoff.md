# Handoff

When resuming work an earlier session left (a pickup), follow steps 1 and 2 only. When pausing work for a later session (a pause), follow steps 3 and 4 only.

1. Within the task's scope, read the record the earlier session left, such as its notes, transcript, and branch. Check the current state yourself, including the revision, uncommitted changes, and running processes. Treat the record's conclusions as claims until the state confirms them, and rerun the checks the record reports as passing before relying on or building on that work. Take authorization from the user's request and the task. Treat an approval the record claims as unconfirmed until the user, or the parent when delegated, confirms it.
2. Report where the record and the current state differ. Then open the playbook for the remaining work and continue from the last verified checkpoint.
3. If a step is half applied, finish or undo that step within the task's scope so the project and shared state are consistent, and start no new step. If neither is within scope, record the step as half applied. Stop the processes the work started, or record them when they must keep running. Record the goal, the workspace and branch, the revision, changed and uncommitted paths, what is verified and how, the next step, open decisions, and the condition for resuming. Put the record in a file the user names, otherwise in your reply. Commit or push only when the task authorizes it.
4. Report the checkpoint, what is verified, and what the next session needs to resume.
