# Coordination

1. State the observable finish condition. Give each Worker one driver who receives reports and issues follow-ups. Assign one owner to each shared write target and route proposed changes for that target to its owner. Name the dependencies and dispatch assignments as their prerequisites are met.
2. Check each new report against the revision or input it covers. If the relevant state has changed, recheck the evidence the next decision needs. Handle each report once. When an assignment needs another round, the driver gives the Worker the next action and what to check. Resume the same Worker when its workspace or checkpoint is needed.
3. For a blocked assignment, have the Worker record what failed, the last verified checkpoint, any proposed change, and the condition for resuming. Route the handoff to the owner who can clear the blocker, through the parent if a direct handoff is unavailable. When the owner reports the dependency resolved, check the current state, resume from a valid checkpoint, and verify the behavior that was blocked.
4. If progress depends on a later event, use a supported wait or wake within the task’s authorization. If the harness cannot resume the run, record the checkpoint and restart condition in a file the user names, otherwise in your reply, and tell the user the run is waiting. On resumption, check the goal, authorization, and current state.
5. Verify the integrated result against the finish condition. If verification fails, route the evidence to the responsible owner for another round that can advance the goal. Report completion when the finish condition is verified. If the user ends the run or no authorized path remains, report why it ended. Include the checked revision or input, what ran, and any gap.
